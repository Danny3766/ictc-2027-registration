## 本機基線

| 項目 | 結果 | 備註 |
| --- | --- | --- |
| 工作樹與分支 | 通過 | `feat/registration-mvp`；本機啟動方式記錄於 README。 |
| Node.js / npm | 未通過 / 通過 | Node `26.12.1` 低於 `package.json` 要求的 `26.13.0`；npm `11.20.0` 符合。PowerShell 請使用 `npm.cmd`。 |
| `npm ci` | 通過 | 依 lockfile 安裝；Node engine 有警告。 |
| `npm audit --audit-level=low` | 通過 | 需信任本機系統憑證；0 個漏洞。 |
| `npm run test:e2e` | 部分通過 | 2026-11-05 加入服事者帳號管理後，以 4 個 worker 對本機伺服器執行 252 項：230 通過、18 略過、4 失敗。預設 worker 數（本機 20 核心為 10 個）同時啟動瀏覽器時，偶有某個測試檔的第一個案例在 `page.goto` 就被中止，頁面程式尚未執行；改用 4 個 worker 後明顯減少，判定為本機平行負載。失敗的 4 項都是 `rls.spec.mjs`：目前開發環境無法直連測試 Supabase，因此資料庫行為改以本機 Docker PostgreSQL 驗證（見下方「本機開家接待資料庫功能」），`rls.spec.mjs` 須在可直連 Supabase 的環境或部署後重跑。先前偶發失敗的完成頁案例，原因是測試在登記頁腳本執行前就前往完成頁；已改為等待活動載入，重複執行 40 次均通過。略過項目為須連接受控 Supabase 的寫入流程、手動執行的截止與限速案例，以及 CSV 案例在非 Chromium 專案不重複執行。 |
| Supabase CLI | 不適用 | 部署環境不使用；部署改用受控 Dashboard 流程，逐版記錄結果。 |
| 本機 PostgreSQL migration | 部分通過 | 保留的 Docker image `postgres:17-alpine` 與容器 `ictc2027-pg-check`；2026-11-04 查詢方式改版後，尚未部署的 7 個 migration 合併為 `202611040001_staff_backoffice_and_name_lookup.sql`；前 6 個 SQL migration 已依版本順序成功套用，並驗證活動排序的成功、重複、缺漏、未知 id 與權限拒絕案例。新增的 `202611040003_activity_time_precision.sql` 因本次驗證時 Docker daemon 未啟動，仍待在乾淨資料庫補驗。容器僅有虛構資料，與測試站 Supabase 無連線。 |
| 本機後台資料庫功能 | 通過 | 虛構管理員與服事者完成帳號 profile 建立、首次改密碼狀態更新、管理設定、補登、匯入狀態、名單修改、作廢（須填原因）與 audit；已驗證服事者不能修改管理設定、不能停用最後一位管理員。實際 Supabase Auth 密碼流程仍待測試站驗收。 |
| 本機公開流程資料庫功能 | 通過 | 改版後以虛構資料驗證：姓名比對忽略全形／半形、大小寫與空白；同區同名有效登記擋下（公開、補登、更正姓名或區）；作廢後查不到且可重新登記；公開修改只改活動選擇、未變更不寫 audit；依來源限速、全站上限與到期恢復；匿名與 `authenticated` 角色無法呼叫 RPC。 |
| 本機開家接待資料庫功能 | 通過 | 2026-11-05 在乾淨的本機資料庫依序套用全部 migration（含 `202611050001_hosting.sql` 與 `202611050002_hosting_review_fixes.sql`；0001 維持測試站已執行的版本，修正另放 0002），以虛構資料驗證：不合法回答（缺欄位、0、小數或超過 99 的人數與家庭數、家庭數多於人數、備註超過 200 字、超出整數範圍）被拒；開關關閉時公開新增不能帶接待、公開修改不能變更接待但查詢仍回傳；開放時公開新增與修改必答；後台補登只在開放時必答；未帶接待的請求沿用已存回答，既有回答不能清除；備註頭尾去除的字元與前端 JavaScript `trim()` 相同；只改備註也會把已匯入改成需重新匯入；audit 記錄接待前後內容；說明文字超過 2000 字被拒；`anon` 無法讀取接待資料表或呼叫相關函式。`supabase/testing/verify-all-no-and-rate-limit.sql` 在接待開關開啟與關閉時都通過。 |
| 本機帳號管理資料庫功能 | 通過 | 2026-11-05 套用 `202611050003_staff_account_management.sql` 後以虛構帳號驗證：新增服事者帳號不需更改密碼、新增管理員帳號須於首次登入更改，且都無所屬區；改名寫入 audit、相同內容不重複寫入、重複名稱與不合法名稱被拒；設定密碼分兩步：事前檢查不登出也不寫 audit（只把管理員目標標記為須更改），密碼改好後才刪除既有 session 並寫入 audit；替服事者設定會清除須更改密碼狀態，替其他管理員設定則要求下次登入更改；傳入所屬區也不會寫入；舊的重設密碼函式已移除；不能替自己設定、`staff` 角色不能操作；audit 不含密碼；`anon` 無法呼叫新函式。`staff` 輔助函式單元測試涵蓋大小寫不同的 UUID 仍視為本人，以及只有 `weak_password` 判定為密碼太弱。 |
| 單元與瀏覽器測試 | 通過 | 公開流程 Playwright 每個專案 22 案，涵蓋查詢確認／修改狀態、未回覆、儲存、取消、未儲存變更提醒、錯誤處理、開家接待開放／關閉，以及頁面載入後開關才改變時保留其他修改；後台每個專案 37 案（含新增帳號設定密碼、改名、設定服事者與其他管理員密碼、自行更改密碼），涵蓋開家接待的編輯、補登依開關必答、統計、CSV、設定與左右兩欄版面。四種瀏覽器專案在 4 個 worker 下均通過；預設 worker 數的偶發中止與無法連線 Supabase 的 `rls.spec.mjs` 見上方 `npm run test:e2e` 列。測試使用模擬 API，仍須測試站實際連線驗收。 |

查看本機容器的虛構登記資料：

```powershell
docker exec ictc2027-pg-check psql -U postgres -d staff_review_check -c "select serial_no, full_name, name_key, district_id, record_status, import_status from public.registrations order by serial_no;"
```

進入互動式資料庫指令列：

```powershell
docker exec -it ictc2027-pg-check psql -U postgres -d staff_review_check
```

`staff_review_check` 是改版後的結構；容器中的 `postgres` 資料庫仍是改版前的結構，不再更新。這些資料不會出現在測試站頁面。容器目前沒有對外開放連接埠，Docker image 和容器都保留供後續驗證。
