## 2026-11-05 試用回饋修訂

弟兄在測試站試用公開頁後回饋：開家接待改成三題、選項用下拉選單；地址下方需要交通資訊；區要有「其他」。

| 討論問題 | 最終決策 |
| --- | --- |
| 開家接待問什麼？ | 第一題「是否可以開家接待？」單選：是／否／家人已登記開家接待（保留家人選項）。選「是」時必填兩個下拉選單：「可以接待幾位？」1～10 位，「接待對象」夫婦／弟兄／姊妹／不拘；兩者預設「請選擇」，未選不能送出。 |
| 人數怎麼算？ | 一律算人數，選夫婦也一樣；單數不阻擋，由服事者判斷。 |
| 家庭與備註？ | 移除「家庭」選項、家庭數與文字備註（含勿填地址電話的提示）。 |
| 已填的試用資料？ | migration 自動轉換：家庭改為不拘，人數超過 10 改為 10，備註與家庭數清空；轉換不改匯入狀態。正式站尚無接待資料。`family_count`、`note` 兩欄先保留為一律 null，因為部署前的 staff Edge Function 仍會讀取；兩個 Edge Function 重新部署後，再以下一支 migration 刪除。 |
| 統計與 CSV？ | 統計顯示是／否／家人已登記開家接待／未回覆的登記數，以及四種接待對象各自的登記數與人數和合計。CSV 接待欄位改為開家接待、接待對象、可接待人數 3 欄。已匯入的登記這 3 欄任一變更即需重新匯入。 |
| 公開頁備註？ | 「網站與登記設定」卡片右欄新增備註（`event_note`），選填、500 字內（網址也計入），顯示在公開頁標題區「地點｜地址」下方，保留換行；`https://` 開頭的網址可點擊並開新分頁，其他內容一律為純文字。地圖建議用分享按鈕產生的短網址。 |
| 區「其他」？ | 由 migration 新增「其他」排在杭州之後，不加說明欄位；查詢、統計、CSV 視為一個區。同名衝突由服事者人工處理。 |

## 2026-11-05 服事者帳號管理決策（最新）

原本改密碼須在資料庫手動處理，因此改為後台直接管理帳號與密碼。

| 討論問題 | 最終決策 |
| --- | --- |
| 管理員可以對服事者帳號做什麼？ | 新增、停用／啟用、修改顯示名稱與帳號名稱、設定密碼。角色建立後不能修改。 |
| 帳號還要指定所屬區嗎？ | 不需要。新增與修改都不再有所屬區；資料庫欄位保留給既有資料，不再使用。 |
| 密碼怎麼設定？ | 新增帳號與「設定密碼」都由管理員輸入密碼並私下交付，對方登入後不需再更改；取代原本產生一次性密碼的「重設密碼」。管理員因此會知道服事者的密碼，請勿透過群組訊息傳送。 |
| 設定密碼後舊登入怎麼辦？ | 對方所有已登入的裝置立即登出，需用新密碼重新登入。 |
| 管理員可以替自己設定密碼嗎？ | 不行。自己的密碼一律用「更改密碼」修改，須輸入目前密碼。 |
| 可以替其他管理員設定密碼嗎？ | 可以，用於協助忘記密碼的管理員；對方下次登入必須改成自己的密碼，新建的管理員帳號也一樣。名單的「密碼」欄會顯示「待更改」，管理員之間應彼此確認已完成更改。 |
| 登入後可以自己改密碼嗎？ | 可以。所有登入者都能從導覽列「更改密碼」修改，輸入目前密碼與新密碼；完成後所有裝置登出。 |
| 帳號名稱改了會怎樣？ | 對方之後要用新帳號名稱登入；名稱不能與其他帳號重複。 |
| 稽核紀錄記什麼？ | 新增、改名、設定密碼與停用都寫入 audit，不記錄密碼本身。 |

## 2026-11-05 開家接待決策（題目與統計已由「試用回饋修訂」取代）

測試站試填後，弟兄回饋希望一併調查開家接待外地聖徒的意願。接待以家為單位，與每人一筆的活動登記不同，因此做成獨立區塊。

| 討論問題 | 最終決策 |
| --- | --- |
| 上線時機？ | 先在測試站完成供試用回饋；正式站與其他活動同在 11/6 12:00 開放。 |
| 接待資料放在哪裡？ | 掛在每筆個人登記上，與活動分開，有自己的欄位與後台設定。不另做家庭登記表。 |
| 有哪些選項？ | 三選一：開家接待／這次不參加開家接待／家人已登記接待。同一家只需一人選「開家接待」，其他家人選「家人已登記接待」，不用填家人姓名。系統無法判斷是否為同一家，重複時由服事者人工比對。 |
| 選「開家接待」要填什麼？ | 接待對象（弟兄／姊妹／家庭擇一）與人數，均必填；人數為 1～99 的整數（2026-11-05 code review 後由不設上限改為最多 2 位數）；家庭數同樣最多 99。選「家庭」時另填家庭數，人數代表所有家庭合計，家庭數不得多於人數。備註選填、200 字內，提示例子只寫居住條件，不提部分天數，並提醒勿填地址或電話。接待回答與活動選擇一樣，知道姓名與區的人可查看與修改，因此地址等聯絡資料不存入本系統。 |
| 必答嗎？ | 開放時必答。新增接待前的登記顯示「未回覆」。 |
| 要選可接待的晚上嗎？ | 不選。選「開家接待」代表整個接待期間；接待期間寫在說明文字。 |
| 後台怎麼設定？ | 管理員後台新增「開家接待設定」卡片，可設定開放開關與說明文字；截止時間與登記共用。 |
| 開關關閉時怎麼處理？ | 開關只控制公開頁。關閉時登記頁不顯示接待區塊；查詢頁仍以唯讀方式顯示已登記的接待內容，並提示聯絡服事者。後台登記資料與補登一律可以填寫與修改。 |
| 後台編輯規則？ | 開關開啟時補登必須回答接待，關閉時可留空（與公開登記一致，也讓部署空檔不影響補登）。修改既有登記時，已回答的接待不能改回未回覆；原本未回覆的可以維持未回覆。 |
| 統計、CSV 與名單？ | 統計顯示四種回覆（含未回覆）的登記數，以及弟兄、姊妹人數與家庭組數、人數。CSV 增加接待狀態、接待對象、接待人數、家庭數、接待備註 5 欄。登記名單不加欄位。只計有效登記。 |
| 匯入狀態？ | 以接待也會匯入大會系統為前提。已匯入的登記，接待 5 個欄位任一實際變更即改為「需重新匯入」；管理員修改接待設定不觸發。 |
| 版面？ | 公開頁接待區塊在活動選擇下方；查詢頁按鈕改名為「修改登記內容」。後台登記資料與補登在寬螢幕分左右兩欄，接待在右；手機排在活動選擇下方。 |
| 上線與開關預設？ | migration 建立的開關預設關閉、說明空白。測試站部署後由管理員填寫說明並開啟。正式站把接待列入 11/6 10:30 go/no-go；通過則 12:00 與 `is_registration_open` 一起開啟，未通過只維持接待關閉，其他活動照常開放。 |

## 2026-11-04 查詢方式改版與 2026-11-05 介面決策（最新）

與會所弟兄討論後確認，目前會所沒有同區同名同姓的情況，因此改以姓名與區識別登記。

| 討論問題 | 最終決策 |
| --- | --- |
| 填寫者怎麼查詢自己的登記？ | 在「查詢或修改登記」tab 輸入登記時的姓名與區。不使用查詢碼。 |
| 查到後可以做什麼？ | 可以查看，並在截止前修改活動選擇。姓名與區是查詢依據，只能由服事者更正。 |
| 同名同區怎麼處理？ | 有效登記的「姓名＋區」不可重複。新登記遇到同名同區時擋下並提示改用查詢；服事者補登與更正姓名或區也適用同一規則。 |
| 姓名怎樣算相同？ | 照填寫內容保存並顯示；比對時先做 Unicode NFKC 正規化，再轉小寫並移除所有空白與零寬字元。支援中文與英文姓名。英文姓名順序、中英文混用、簡繁體不同時視為不同姓名，頁面提示「寫法須與登記時相同」。 |
| 查詢碼怎麼處理？ | 完全移除，包括資料欄位、伺服端 pepper、完成頁顯示與後台重設功能。 |
| 疑似重複流程怎麼處理？ | 移除「可能重複」與「確認為不同人」。 |
| 登記填錯、惡作劇或不參加怎麼處理？ | 服事者可將登記「作廢」並必須填寫原因。作廢紀錄保留供查核，不計入統計與 CSV，也不佔用姓名與區，正確的人可以重新登記。不提供永久刪除或頁面上恢復。 |
| 公開操作如何防濫用？ | 公開新增、查詢與修改依來源限速，成功與失敗都計入，並有全站上限；額度到期自動恢復，不再全站永久暫停。具體門檻與偵測條件不公開。 |
| 是否保存 IP？ | 不保存原始 IP。限速只短期保存以伺服端金鑰保護的 IP 雜湊，時間窗過後自動刪除。 |
| 完成頁顯示什麼？ | 保留獨立完成頁，顯示這次送出的姓名、區與各活動選擇，並提示日後以相同姓名與區查詢。重新整理仍保留摘要；回到登記頁時清除，避免共用裝置的下一位看到。 |
| 既有測試資料怎麼處理？ | 套用改版 migration 前清空測試站登記資料，請試填者以新流程重填。 |
| 發現濫用時如何緊急停止查詢？ | 網站設定新增「開放公開查詢與修改」開關，管理員取消勾選即停止公開查詢與修改；與「開放登記」分開設定。 |
| 後台要顯示稽核紀錄嗎？ | 不顯示。`audit_events` 照常記錄，用於追查修改、保存作廢原因與改密碼限速。 |
| 活動順序怎麼調整？ | 新增活動時排序可留空，系統會自動排在最後；後台活動表按「調整排序」後出現 ☰ 欄，可用滑鼠、觸控或方向鍵拖曳；按「完成排序」一次儲存，「取消」還原。手機上排序時只顯示名稱、類型與 ☰。排序不影響匯入狀態。 |
| 活動日期與時間怎麼設定及顯示？ | 後台將開始與結束的日期、時間分開輸入，時間選填。公開登記頁顯示活動日期；有設定時間時一併顯示台灣時間，同日開始與結束時間以區間呈現。 |
| 查詢登記後如何確認與修改活動選擇？ | 查詢成功先以中性純文字顯示「參加／不參加／未回覆」，不可直接操作；按「修改活動選擇」（2026-11-05 改名為「修改登記內容」）才顯示 radio、儲存與取消。沒有實際變更時不能儲存；取消、切換頁籤、重新查詢或離開頁面時，只有存在未儲存變更才提醒。儲存成功後回到確認狀態。首次登記完成頁維持精簡摘要；移除「未回覆」狀態另案處理。 |
| 區可以停用嗎？ | 不可以。會所的區固定；移除停用功能與 `districts.is_active` 欄位。後台不顯示區選項管理，`staff` Edge Function 也不接受新增或修改區，避免改名後既有登記的「姓名＋區」查詢對不上。 |

### 開放 gate 與豁免

下列五項為不可豁免 gate；任一項未通過，11/6 12:00 維持關閉：

1. 前端、GitHub Pages artifact 或公開內容沒有 `service_role`、密碼或其他 secret。
2. 匿名使用者不能直接讀取或修改登記、後台帳號、audit 等敏感資料。
3. 正式網站沒有連到測試 Supabase，測試網站也沒有連到正式環境。
4. 建立登記可以成功，且不會產生錯誤、重複或損壞資料。
5. `admin` 能立即關閉公開登記與公開查詢／修改。

除上述五項外，日期優先；其他失敗可由 release owner 核准豁免後開放。每項豁免都須記入 `docs/驗收紀錄.md`，至少包含：

- 未通過項目與實際結果。
- 對使用者與資料的風險。
- 暫時緩解方式。
- 預計修正日期。
- Release owner 的核准與核准時間。

沒有上述紀錄的失敗項目不視為已豁免。一般資安強化、外觀與非阻擋改善可在開放後補上。

### 測試與瀏覽器

| 討論問題 | 最終決策 |
| --- | --- |
| 自動測試哪些瀏覽器？ | Playwright 自動測 Desktop Chromium、Desktop WebKit、Mobile Chrome 與 Mobile Safari 模擬。 |
| 能否以 Playwright 代表真正 Safari？ | 不能完全代表。Playwright WebKit 用於自動測試；11/6～11/7 另使用實際 Apple 裝置的 Safari 驗收。 |
| 測試是否操作遠端資料庫？ | 可以操作開發／測試 Supabase 專案。每次測試使用唯一 run ID，完成後只清除自己的資料，不重設整個共用專案。 |

### 分支、部署與環境

| 討論問題 | 最終決策 |
| --- | --- |
| 分支如何流動？ | 每次從 `測試分支` 建立新的 feature branch；完成後先合併回 `測試分支` 作為測試環境。要上線時，再由 `測試分支` 合併至 `main`。 |
| 哪個分支部署正式站？ | `main`。GitHub Pages 正式站只部署 `main` 的網站成品。 |
| Supabase 環境如何隔離？ | 使用兩個 Cloud 專案：一個供開發／自動測試共用，一個供正式環境。11/3 建立開發專案，11/5 前以相同 migration 建立正式專案。 |
| Supabase 建置由誰處理？ | 使用者需要從零開始的逐步協助；由 wizard 引導帳號與專案建立、環境隔離、憑證安全保存、部署與連線驗證。不得假設使用者熟悉 Dashboard。 |
| 部署內容包含哪些檔案？ | 只發布明確的網站成品目錄；不得把 SQL、測試、規劃文件、`node_modules` 或 secrets 上傳成 Pages artifact。 |
